---
title: "Устранение неполадок"
description: "Типичные проблемы развёртывания PowerDNS Web UI и работы API."
---

## UI не может подключиться к PowerDNS

Убедитесь, что `PDNS_API_URL` доступен с машины или контейнера, где работает
PowerDNS Web UI.

Из этой среды:

```bash
curl -H 'X-API-Key: your-key' \
  "$PDNS_API_URL/api/v1/servers/$PDNS_SERVER_ID"
```

Если это не сработает, сначала исправьте сеть, конфигурацию веб-сервера
PowerDNS или API-ключ, прежде чем отлаживать UI.

## Ответы 401 или unauthorized

Значение `PDNS_API_KEY` должно совпадать с `api-key` в `pdns.conf`.

Перезапустите PowerDNS после изменения `pdns.conf`.

## 404 для сервера или зон

Проверьте `PDNS_SERVER_ID`. В большинстве установок используется:

```dotenv
PDNS_SERVER_ID=localhost
```

Если ваш API использует другой идентификатор сервера, укажите его.

## Docker не может обратиться к PowerDNS на localhost

Внутри контейнера `localhost` означает сам контейнер.

Используйте вместо этого доступный хост, например:

```dotenv
PDNS_API_URL=http://pdns:8081
```

для другого сервиса Compose или адрес моста хоста, если PowerDNS работает на
хосте Docker.

## Записи ALIAS не разрешаются

Убедитесь, что PowerDNS настроен на расширение ALIAS:

```ini
resolver=[::1]:5300
expand-alias=yes
```

Резолвер не должен указывать обратно на сам authoritative-сервер.

## Не удаётся передать slave-зону

Проверьте метаданные первичной зоны и сетевой путь:

- `ALLOW-AXFR-FROM` включает вторичный сервер
- Первичный сервер принимает TCP/53 от вторичного
- Адрес master зоны корректен
- Межсетевой экран разрешает передачу
